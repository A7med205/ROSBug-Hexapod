The @/gait_control.cpp contains the ROS based gait controller for a simulated hexapod, I want to port it to a MycroPython based real robot by modifying @/board_cluster.py and @/rpi_master.py which run on a Servo2040 board and an RPi via serial communication:

- Remove all the ROS related code and re-write in Python, the end result should work similarly to how @/board_cluster.py currently works by updating pulse values instead of sending points to an action server.

- Keep the structure as similar as possible.

- The hard-coded parameters in @/gait_control.cpp should remain hard-coded in @/board_cluster.py.

- An additional function needs to be added to convert the generated joint angles from the robot's system to each servo's calibrated system (use @/robot_to_servo.txt as reference) and to convert these angles to pulses (use @/angle_to_pulse.py as reference).

- "step_length_", "step_height_" and "step_duration_" should be hardcoded inside @/rpi_master.py and sent from the RPi inside each command similar to how @/rpi_master.py and @/board_cluster.py communicate currently.

- Add an additional non hard-coded "step_direction_" parameter, which should modify the angle inside the "leg_configs_" data structure depending on the button press received by @/rpi_master.py; "w" should use the same current "leg_configs_.rotation_angle" values, "d" should use them with 90 degrees added, "s" should use them with 180 degrees added and "a" should use them with 90 degrees subtracted. The logic is that these values would change the robot's movement direction becasue of how the "rotate_coordinates()" function affect's every leg's path.

- instead of "total_full_steps_", @/board_cluster.py should check with @/rpi_master.py and @/rpi_master.py should send a new step command if a button was pressed within the last 100ms.

- At startup, "servos.enable_all()" all servos in a starting position, after that all legs should Move to the hard coded Y and Z position in two steps, first X=0, Y=Y, Z=0 and then X=0, Y=Y, Z=Z, basically a touch the ground then stand-up sequence. 

- Don't try to run tests, this is not the robot environment.
